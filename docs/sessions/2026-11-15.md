## Lessons about agents
- Context lives in three layers: the agent file (role, standards, where truth lives), the brief
  (this job), the repo (facts). Point to facts; don't copy them into the agent file.
- Test an agent's tools with a tiny job first, and use a control (a general agent) to tell
  "this agent is misconfigured" from "subagents can't do this".
- Edits to an agent file take effect from the next message, not mid-turn.
- In cloud sessions, MCP tools (GitHub) load on demand, so an agent needs `ToolSearch` as well.
- Agents don't talk to each other; hand-offs are saved documents in `docs/designs/` the owner can edit.
- Always check an agent's report against the repo (the Architect got a deadline wrong), and fix the
  layer that caused a mistake (definition, brief or docs), not just the output.
- A research helper's WebFetch couldn't reach newly allowed hosts; curl through the proxy could.
