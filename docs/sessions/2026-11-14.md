## Gotchas
- **Deck routing:** the page can fire tasks (`fire_trigger`) but apparently can't use
  `send_message`. Task-fired *fresh* sessions get no repo, and so no GitHub access. That's why
  background syncs go to a persistent session with the repo attached.
- **`R2_ENDPOINT`:** the GitHub secret has surrounding whitespace. The collector strips it, so
  it can stay as is.
- GitHub scheduled workflows only run from `main`. Test changes with "Run workflow" on a branch first.
- A *new* workflow file can't be dispatched until it's on `main`. For one-off jobs, add a switch to
  `collect.yml` and run it from the branch (that's how the bonus data was explored).
- wago.tools publishes WoW Forever's game tables under `?branch=wowf`. Retail and Raidbots data
  don't have Forever's bonus IDs.
- The first scheduled run started ~50 min late (01:27 slot ran at 02:17). Check this in #28.
- **What a "house" is (city? server?) is unknown.** Prices don't pair houses into Alliance/Horde/
  Blackwater "worlds" (similarity follows house size). The prototype has an in-game check: compare an
  item's cheapest price at two cities' auction houses, then match against that hour's data (#13).
- Ruleset doesn't change the auction data: every ruleset returns the same houses.
- To read R2-only tables from a session, a temporary `collect.yml` switch can print them to the
  Actions log (used once for the version names, then reverted).
- R2 can't be read from Claude's cloud sessions (the keys can't go through the proxy). Checking
  stored data needs a workflow or the Actions logs.
