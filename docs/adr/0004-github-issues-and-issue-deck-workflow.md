# 0004. GitHub issues as the work tracker, with the Issue Deck

- **Status:** Accepted
- **Date:** 2026-11-13
- **Issue:** PonchoAndy/DayTrader#1

## Context

Work spans you (accounts, decisions, in-game checks) and Claude (code, research). We need one
place that shows what's next, who owns it and what's blocking it, and it should be easy to
answer from a phone.

## Decision

- All work is a GitHub issue with a type prefix (Decide / Setup / Build / Research / Tracking),
  plus **Who**, **Blocked by** and **Done when**. See `docs/WORKFLOW.md`.
- Commits reference issues (`Refs #N`); PRs close them (`Closes #N`).
- You read and reply through the **Issue Deck**, a private claude.ai page of swipeable cards.
  It has no GitHub access of its own: replies wait in the page's storage until you ask Claude
  to "sync the Issue Deck", which posts them, closes issues marked done, and refreshes the
  cards. Steps are in `CLAUDE.md`.

## Consequences

- No accounts or connectors to set up for the Deck.
- The Deck is only as fresh as the last sync, and replies post under your GitHub account with
  a "Generated by Claude Code" footer.
- Labels aren't used yet (they couldn't be created from Claude's tools); title prefixes do the job.

## Alternatives considered

- **One long checklist issue:** hard to track and discuss item by item.
- **Live GitHub connector in the Deck:** your claude.ai account has no GitHub connector, so
  the page couldn't call GitHub directly.
